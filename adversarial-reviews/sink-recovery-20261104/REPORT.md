## Evidence and scope

The retained fixed probe records acknowledged authority calls 201/200/201, then process kill/restart, authority 2 and two recovered effects; stale/current uses return 409/201. Its obligation case records 201/200 before kill and exact retained payload delivered with 201 after restart. In the retained baseline, restart resets authority to 1, accepts stale use, rejects current use and fails obligation delivery; its source hash is `516b48d81012207f1d736304ba12ac4fdf5595e927e359a3ae5b5c9d0332f702`, not the fixed source. For both, I decoded the journal snapshots and independently recomputed every recorded snapshot hash. The fixed authority's persisted sequences go 1,2,3 then 1,2,3,5 (a rejected diagnostic consumes 4); the gap control independently records 1,3,4 then 1,3,4,5. All ten retained refusal controls report nonzero exit and empty stdout; they are selected controls, not proof of complete validation. I inspected the corresponding harnesses; their recorded fields and selected assertions align with these observations. No producer probes were rerun; the single new disposable process execution is the Boolean counterexample above.

A journal consisting of a valid shorter prefix, or one missing a whole durable record without detectable semantic inconsistency, cannot generally be distinguished from a current journal: gaps are permitted and there is no external witness. This is a limitation of unqualified 'missing material' refusal; correct/current journal is an explicit premise, and no rollback or root authentication was claimed. Replay also caps input at 65,536 bytes; source append does not appear to enforce a matching size limit, so the broad reconstruction claim requires a bounded-journal qualification if acknowledged writes can grow beyond that threshold. This size observation is source-based, not an executed extra test.

The frozen `Phase-I-Verification.md` §3 T18 asks that post-revocation use-current acceptance be excluded by actual sink ordering, and exact obligations remain deliverable after replacement. These local restart observations support the selected analogues, not complete T18. §5 F4 requires interruption across a much wider set of boundaries, storage-call evidence when relied on, and explicitly distinguishes process termination from power loss. This check does not establish full F4, production sink behavior, complete schema validation, nonrollback, root authentication, power loss, or exhaustive schedules. The Boolean fault is a parser/product validation issue on intentionally malformed input, not a failure of the probe harness or a demonstrated valid-writer history.
