# P3 — Missed by five controls, detected by existing coverage and independent boundaries

**Result: PASS for this targeted experiment.** Six deliberate source-level mutations (capacity, prepaid wallet floor and postpaid spending cap in Rust and Haskell) compiled and ran. The **five P1 controls missed all six**, the **preexisting 1,025-case reference corpus caught all six**, and the **six independent boundary controls caught all six** while preserving their valid nearest neighbors.

## Costs, overhead and method findings

- Focused mutation qualification: **7,197.183 ms** (including six mutant builds and execution).
- Entire GitLab job: **72.386 seconds**, including provisioning, source fetch, package installation, initial compilation and artifact upload.
- Full structured output file: **37,494 bytes** according to the CI harness. Hash-qualified CI artifacts were uploaded and local integrity rechecked after writing; the complete **independent external archive was NOT_VERIFIED**.
- An earlier attempt selected the large replication job due to an incorrectly escaped CI rule; it was cancelled rather than run unnecessarily. A subsequent trial was cancelled to correct an instrumentation import path before it produced behavioral observations. Neither should be scored as an assertion failure or a mutant kill. Both remain in GitLab pipeline history.

The most useful result is *not* that mutation testing is always mandatory. P1's small suite gave accurate results for the particular consent rule it claimed to test, but did not substantiate capacity or funding-cap invariants. The much larger inherited corpus already detected these three broader deviations; the six additional paired controls produced **more compact, human-auditable boundary witnesses**.

The legacy generated corpus shares a Python oracle with the reference implementations. It therefore cannot alone rule out correlated specification mistakes. The new boundary expected values are **literal declarations made before execution**, not derived from the current program output. Their reliability is still conditional on correct requirement interpretation. None of these three selected mutants measures a general mutation score, exhaustive program verification, or actual distributed resource-admission races.

## Scope and next discriminator

Choose the next assurance method by the claim, not by mandating more mutation runs: a bounded, seeded **metamorphic/property-based test** would add evidence about invariants that do not require a copy of the existing oracle, while concurrent reservation and delayed account reconciliation require a different stateful system than this one-shot baseline.

**P1/P2/P3 are research evidence, not authorization to promote the testing-and-assurance draft.** Independent reviewer reconstruction remains NOT_RUN; full external CI archive for P3 remains unverified. Methodology decision: **DEFER**.
