# Pilot P1 — Observations, qualification and limits

**Decision: DEFER adoption of the draft assurance method.** The first pilot provides favorable scoped evidence for paired controls, source-mutant sensitivity and archive-integrity fault detection. It is **not** evidence that the complete proposed method, a production financial gate, or either implementation language is verified. No human-authorized methodology or language-selection policy changed.

## Before-run plan and evidence provenance

- The frozen [P1 pre-registration](P1-PREREGISTERED-PLAN-2026-11-01.md) was committed at `33d2781279cf85784a6fb880c8bb3a9a90d90130` **before** writing/running this pilot's mutations or archive checker. The emitted plan SHA-256 in both execution records is `33493c4d4b5cf9931fc08105cbc1a27f341bcd07a8dc1faae8bc52a748607971`.
- The object under test is the synthetic Rust/Haskell **one-shot** admission contract from the already-existing language-evaluation spec. It does not make claims about provider billing or real distributed reservations.
- Preregistered claim C1: unauthorized positive spend must fail; paid-authorized neighbor must pass.
- C2: valid free/paid requests must not be rejected by a safety test.
- C3: missing or tampered evidence must be distinguished from failing software behavior.
- C4: qualify the selected checks by targeted mutations and measure their cost.
- Qualified techniques: exact source-level faults to the same two implementation paths and a synthetic archive fixture. No new state-machine realization, general mutation-score threshold or blanket CI gate was introduced.

## Interpretation separated from observation

| Claim | Evidence / interpretation | Status |
| --- | --- | --- |
| C1: Paid authorization safety check discrimination | Each intended guard removal is caught by both independent compiled language variants; authorized neighbors still pass | SUPPORTED_WITHIN_SCOPE |
| C2: False-rejecting safe examples is detected | Each final-acceptance mutation is caught by valid neighboring controls, without losing negative rejection | SUPPORTED_WITHIN_SCOPE |
| C3: Integrity detection works | Synthetic corruption/missing checks pass; the first CI wrapper had a write-after-index race, now addressed with post-write verification | PARTIALLY_QUALIFIED; external archive unresolved |
| C4: Method has finite observable overhead | The selected qualification steps took ~4.4 seconds; two shared-runner full pipelines took approximately 91.8 and 92.1 seconds. Setup, large existing benchmark suite and CI variability dominate pipeline duration | OBSERVED for this pilot only |
| Independent reviewer can reconstruct research decisions | Preregistered plan, source revision, machine observations, original instrumentation failure and corrections preserved | NOT_YET_REVIEWED by an independent reviewer |
| Real resource-solver / billing assurance | No real paid resources, provider settlement, crash recovery, concurrent transactional reservations or external account data tested | NOT_TESTED |

The method added measurable discrimination on the intentionally selected faults. It does **not** yet show that the proposed process improves long-term project reliability relative to ordinary tests; all mutants were constructed explicitly to target existing controls, so a 4/4 result cannot be generalized into a mutation-score claim.

## Methodology evaluation / next smallest discriminators

1. **Independent reviewer reconstruction** from just frozen plan, schema, source revision, machine evidence and conclusion. Measure missing facts and reviewer effort rather than accepting agent agreement as evidence.
2. **Second unlike substrate** per draft §11 (prefer a safe existing Trip'n production-invariant Action, not a live booking/payment). Capture failures and successes with actual full diagnostic artifacts without exceeding GitHub retention.
3. **Independent complete CI artifact export**, including failed/cancelled/skipped runs when accessible; test intentional exporter failure with a separate diagnostic. At present only a subset of result files and their complete hash index are copied to GitHub.
4. Test a mutant **not** directly targeted by preselected controls (or a constrained property-based generator), to measure limitations of control selection rather than only proving four known mutations can be killed.
5. Measure cumulative agent/token overhead, archive size and ability to reconstruct decisions across these two substrates; accept or reject the method based on marginal assurance value.

**Acceptance remains DEFER.** The original draft is unchanged. This report is a research result, not a promotion of the proposal into canonical ASES methodology.
