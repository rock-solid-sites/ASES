# P5: Conventional restart checks versus qualified SIGKILL tests

**Observed result: Scoped method-comparison PASS.** Normal-operation/restart/idempotency checks (approach A) found a deliberately introduced duplicate-commit fault but **missed** a second fault that sent an acknowledgement before the journal was durable. Adding milestone-qualified SIGKILL checks (approach B) **detected both faults**, in Rust and Haskell, while the correctly ordered implementations passed both approaches.

This is a **controlled two-fault demonstration**, not an unbiased defect-discovery rate or proof that ASES's whole methodology is better than conventional testing in general.

### Approach A — conventional regression suite

For each implementation and mode: commit an authorized request, restart a *new process* and inspect state, retry the same request ID (must not duplicate the charge), reject an unauthorized paid request, and reject individually over-capacity and over-spend-cap requests. Check that rejections do not mutate persistent state. This is a credible ordinary suite, not a deliberately empty or broken control.

### Approach B — same regression suite plus checkpoint-qualified interruption

On top of approach A, start a process with an explicit barrier, wait for exact emitted milestone, send `SIGKILL` to **that child**, confirm its exit status, start a separate recovery process, inspect persistent state, and retry as appropriate. Independently repeat five times for three checkpoints:

| Checkpoint | Requirement |
| --- | --- |
| `PREPARED`, before append | No committed reservation; a retry may commit once |
| `DURABLE`, after journal append and successful `fsync`, before ACK | One committed reservation; retry cannot duplicate |
| `ACK`, immediately after acknowledgement | Already committed and recoverable; acknowledgement implies durability |

The exact kill point was verified through barrier markers, signal exit `-9`, journal recovery and SHA-256 of the resulting test journal. It was not inferred from a random short delay.

## Initial RED was a test-fixture error, not a product defect

[First GitLab pipeline 3015831687](https://gitlab.com/rock-solid-sites-group/rock-solid-sites-project/-/pipelines/3015831687), job `17650922007`, compiled both languages and exercised the crash checkpoints. It failed its overall P5 assertions because the **conventional test wrongly expected a charge of 50 cents to exceed an 80-cent spending cap on an empty journal**. Both correct implementations properly admitted that request. The benchmark harness therefore recorded `BEHAVIOR_FAIL`, but the independent diagnosis classified the underlying issue as a **test-oracle/fixture error**.

The fixture was corrected to 90 cents against an 80-cent cap in commit `0e25c4b8970a0064af4d4169f68f5ac7e0cfab2e`. The test plan was **not retrospectively modified**. The first failed CI archive is preserved separately.

## Corrected machine observations

| Tested code | Rust A | Rust B | Haskell A | Haskell B |
| --- | --- | --- | --- | --- |
| Correct fsync-before-ACK implementation | PASS | PASS | PASS | PASS |
| Duplicate-ID protection disabled | DETECTED | DETECTED | DETECTED | DETECTED |
| ACK issued before append/fsync | MISSED | DETECTED | MISSED | DETECTED |

For each language, B ran **45 checkpoint kills** (3 modes × 3 checkpoints × 5 repetitions), totaling **90 targeted SIGKILL tests** over the two languages. The correct modes passed **30/30** checkpoint tests. The intentionally defective modes produced the expected violations: duplicate-ID fault after `DURABLE` and `ACK` (5/5 at each point per language), and early-acknowledgement fault when killed immediately after `ACK` (5/5 per language). The `PREPARED` control and legitimate neighboring cases continued to behave correctly.

The early ACK problem was deterministic and attributable: after receiving ACK, the harness killed the still-blocked worker before its journal write; a restarted process found no committed transaction. Ordinary successful process exits had completed writing, so approach A's restart tests could not reveal this ordering problem.

## What the method experiment establishes

**Supported within scope:** checkpoint-specific fault injection added useful sensitivity beyond a reasonably selected conventional suite; credible positive controls kept false-rejection risk visible; explicitly confirmed process-kill markers and separate recovery processes made the fault attributable; small additional test execution cost is measurable; preserving both red and green archives prevents retrospective cherry-picking.

**Not established:** universal superiority of method B, unbiased mutation-score estimates, general production durability, protection against power failure or storage-cache loss, directory creation metadata durability, multi-process or distributed transactional isolation, actual provider billing, partial/garbled journal recovery, nor independently measured reviewer reconstruction accuracy.

**Additional caveat:** the injection faults were chosen prospectively and deliberately matched the hypotheses, which improves discrimination but can bias method-comparison results. A later blind defect pool or independent implementation/reviewer is necessary to estimate real detection lift without choosing faults to favor B.

**Methodology adoption and Rust-versus-Haskell language decisions: DEFER.** The recommended next discriminator is a blind reviewer reconstructing the journal/ACK timeline directly from this complete archive without reading the author's result narrative, followed by a second non-planted fault or model-derived interleaving.
