# ASES scheduler observation repair — 2026-11-03

Status: **research branch; tested, awaiting review**. This investigation uses the ASES experiment-specific [EVIDENCE-CLASSIFICATION.md](EVIDENCE-CLASSIFICATION.md), not a new global policy. No production schedules, Cloudflare dispatch flags, credentials, issue state or Trip'n monitors were changed.

## Errors actually isolated

1. **GitHub observer route failure:** the connected GitHub tool rejects the workflow-specific `/actions/workflows/{workflow_id}/runs` URL as an unsupported route (HTTP 400 at the connector boundary). The repository-wide `/actions/runs?event=schedule&per_page=100` endpoint works. This is not evidence of a GitHub scheduler outage. Filter returned `workflow_runs` by **exact** `workflow_id` and `event=schedule`, and verify pagination reaches an entry before the eligible observation window.
2. **Incorrect narrative lower bound:** ASES run 41530651460 at 21:41:32 UTC was incorrectly compared with a nonexistent 19:13 three-hour cron slot. The latest *possible* eligible slot was 21:13, so the correct minimum delay is **28m32s**. Trip'n run 41530373728 at 21:39:43 has latest possible slot 21:07, so minimum delay is **32m43s**. These are lower bounds only; native schedule events cannot identify intended slots. The 10:54:58 and 10:52:42 executions have lower bounds 1h41m58s and 1h45m42s.
3. **GitLab activation gap:** project 88367140 has validated CI execution on an isolated branch, but the installed GitLab connection cannot inspect or create pipeline schedules. Pipeline listings with `source=schedule` have zero entries. That does **not** prove missed triggers, because both intended schedule definitions and activation are unverified.

## Implemented repair

- `readback-v2.mjs` generates UTC nominal slots, computes conservative lower bounds and normalizes GitHub repository-wide result collections. Malformed responses become `OBSERVER_UNAVAILABLE`; inadequate page depth/order becomes `OBSERVER_PARTIAL`. Duplicate run IDs are rejected. Unsupported direct workflow-route errors must be recorded as connector capability failures and retried through repository-wide readback.
- `classify.mjs` preserves all v0.1 baseline behavior but enriches new run events with calculated lateness evidence and conditionally includes GitLab classifications.
- GitLab metadata cannot be upgraded from `CONFIGURATION_UNVERIFIED` until **both** intended schedule records are read, active, correct in description/cron/UTC/target branch, and expose schedule ID, creation time and next-run time. Even then the first eligible activation time remains a separate measurement; expected slot count is not inferred from configuration creation alone.
- `readback-v2.test.mjs` includes adversarial edge cases. Run `node --test readback-v2.test.mjs classify.test.mjs` with Node 22.
