## Repair decision

No minimal source-code fix is justified yet. The current failing invariant is **not established**: Cloudflare’s clock invariant passes; GitHub exact-slot attribution is unavailable; GitLab schedule configuration has not been observed. The GitLab gap is currently an evidence-access/configuration boundary, not a localized repository defect. Enabling dispatch, changing workflow schedules, or inventing GitLab schedule definitions would alter the experiment rather than repair a reproduced defect.

The next discriminating test is authenticated, read-only inspection of the two intended GitLab schedule definitions, including their cron expression, timezone, target branch, active state, creation time, and next-run time. If both are active and correct, preserve that activation boundary and compare one bounded future schedule window against source=schedule pipeline records. If a definition is absent or incorrect, treat that as a provider configuration issue and make only the separately authorized configuration change needed to restore the stated experiment.
