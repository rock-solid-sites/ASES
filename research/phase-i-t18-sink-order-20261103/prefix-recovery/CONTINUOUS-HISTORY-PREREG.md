# Continuous serving history without restoring captured journal fixtures

Earlier prefix tests deliberately copied bytes from a prior executed I/O-failure record into fresh roots. They establish replay/cut behavior for those byte fixtures, not one continuous original-ACK-to-recovery serving history. New F4 discriminator removes that fixture boundary: initialize a fresh actual sink, receive one real ACK, physically partially append next record via the existing scoped API shim, observe no response and latched later no-response, kill/reap, then explicit prefix recovery consumes the SAME surviving journal file. No oracle writes journal/authority bytes after initialization.

Reuse unchanged io-failure/probe.case for the actual failed writer and strict refusal, then prefix recovery gates on its root/state journal. Four schedules: no intermediate kill, kill after quarantine, kill after prepared prefix fsync, kill after prefix publication; all before readiness. After each loss fresh recovery must expose exact original ACKed effect, no incomplete/blocked effects, preserve original quarantine, ACK a new current effect, and retain both through strict restart. Test compares actual ACK to observations but supplies no remembered ACK boundary/state to recovery.

Instrument only supervisor Popen creation/exit metadata to retain every owned child PID/argv/monotonic start; capture existing exact request/reply/gate/filesystem observations. Derive common selected history order from invocation/completion and process boundaries. Read-only checker must support all positive histories, classify removal of an actually ACKed recovered effect as VIOLATION, missing old ACK/timestamp/process boundary as INCOMPLETE, never deny unknown requests merely because no reply. Controls mutate observations only, not implementation/source logs. Four finite same-live-host histories, no exhaustive protocol refinement proof.

One sink/reader child at a time,45s outer/4s processes/256MiB, journals<16KiB and all files<256KiB/root, explicit cleanup/reaping. Existing append-only new-unACKed-tail/current-root/sole-writer premises unchanged; arbitrary ACKed-record truncation remains known contrary control. API exception deliberately injected after real bytes, not spontaneous physical disk fault. No power loss, external effects, nonrollback or aggregate F4/F1 closure.
