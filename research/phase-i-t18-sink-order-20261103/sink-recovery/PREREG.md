# Real sink restart after acknowledged replacement and exact obligation

Base31118f0 has a write-all fix, but current SinkState initialization only reads journal in f4 mode, does not reconstruct authority version or obligations, and resets other modes to version1. Prior experiments used fresh journal readers, not cold serving sink restart. New F4/T18 question: does the same selected sink reconstruct previously acknowledged replacement and exact obligation when killed/restarted from the same journal?

Reference candidate obligation for this extension: complete current journal preserved by live host across SIGKILL/reap must reconstruct version2, deny old version1, accept current version2 and deliver the exact previously committed obligation. This is not retrospective expansion of prior profile claims or frozen F2 execution; it is newly tested process-loss extension. No rollback-resistant or power-loss premise.

Two independent roots, sequential cases. Authority: accept current v1; replace and fully observe version2 ACK; accept v2; kill/reap; restart sink-ordered on same root; record pre-request status/journal; then stale v1 and current v2. Prediction for baseline: restored version1, old accepted and current denied, memory trace reset despite retained journal. Obligation: commit q with exact payload/digest; replace ACK2; kill/reap; restart same root; deliver q. Prediction baseline: missing obligation denied despite retained committed record. Before-kill positives genuine. After-restart request IDs distinct; preserve raw bytes and do not infer seq continuity when state reset reuses IDs.

At most one sink at a time plus fresh reader if needed, 4s call/process bounds/30s outer/256MiB per owned process, journals<64KiB. Keep both failures as research counterexamples to extension, not aggregate F4 defect/closure. If baseline fails, smallest correction must replay validated durable record kinds before ready, preserve max durable sequence for further append, distinguish recover-existing from trusted bootstrap, reject truncated/missing/unsupported state in recovery mode, and preserve both use-current and exact-obligation profile distinctions. Freeze correction gate after observing baseline. No schema/ontology promotion, protected-host claim, retry deduplication, actual power loss, external authority witness or arbitrary sink correctness.
