# F4 gate and recovery artifact qualification — preregistration

The original `F4-results.json` records client outcomes and cold results but not the live status snapshots used by `wait_for_event`; its reader maps nonexistent and empty journal to the same empty result. Preserve all original artifacts. A separate rerun uses the unchanged `run.py` local sink, event gates, client and journal writer; the new test observes them rather than modifying the implementation or frozen F2 expectations.

Four independent one-request cases use distinct temporary roots and the same exact bounded UTF-8 payload: uninterrupted, preaccept wait, accepted-and-fsync-returned-before-ACK wait, and unsafe early-ACK wait. For every case record client process PID/response/exit, sink PID/kill start/reap/exit, monotonic supervisor markers, the actual sink `/status` snapshot including named gate and `seq`, and journal existence and raw bytes/hash before and after kill. In the accepted-before-ACK case, wait for the actual `accepted_waiting_before_ack` event; source inspection shows it is emitted only after the preceding effect append and `fsync` call returned. While the sink remains alive and held, a separate reader process must independently open and parse the extant journal, recompute exact payload hash/bytes, and return one effect; after SIGKILL/reap another fresh reader must agree, while the client reports no response. This observation/source ordering does not instrument an OS `fsync` syscall or prove power-loss durability.

A distinct strict read-only subprocess reports `MISSING` on `FileNotFoundError` and parses only an existing file; it never represents missing as a successful empty journal. Record actual existence, process exit and result; absence before acceptance is not fabricated as a denial. Explicit additional control creates an existing zero-byte file and confirms a separate reader identifies it as `EMPTY`; a missing-path control identifies `MISSING`. An existing malformed/truncated line must be refused, not empty. The uninterrupted positive control has a success response and exact reader-verified effect; early-ACK unsafe case must expose success before kill while no recoverable effect record exists. If a gate, file or response is missing/ambiguous, preserve that state as incomplete and do not assert a passed ordering. The source-selected sink acceptance boundary remains append+fsync return; no new sink/runtime or physical authority policy.

At most one sink and one client at a time; bounded payload <1 KiB, journal <64 KiB per case, per-process/pipe 4-second timeouts, 30-second outer timeout, one 256 MiB address-space cap per process; explicitly reap or kill/reap every owned child on timeout, disposable temporary directories only. Record raw JSON, exact source/runner/reader hashes, exit statuses, dates, platform and commands. This is four fixed local process-loss histories plus empty/missing/truncation controls, not F2 T07 power loss, power-loss storage proof, F3 host confinement, full F4, retries, or an unbounded sink guarantee. Prior raw evidence remains byte-for-byte unchanged.
