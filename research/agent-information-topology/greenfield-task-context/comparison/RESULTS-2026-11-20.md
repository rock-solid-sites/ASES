# Task-scoped context: preregistered 2 × 3 comparison results

**Status:** Completed non-model synthetic baseline; **not** a production architecture decision or evidence of agent-model compliance.

**Source:** `cases.json` contains the frozen common synthetic facts and expected rule/source IDs; four packets were hand-authored (`packets/*.md`) from those facts; the fifth/sixth comparison packets were rendered by the tiny test-only graph resolver in `evaluate.py`. The three mechanisms were evaluated using the **same exact-string oracle**, not against three different acceptance criteria.

**CI evidence:** [Actions 44767619586](https://github.com/rock-solid-sites/ASES/actions/runs/44767619586) completed successfully, recording the six result objects in its job log and compact table in its job summary. The combined unit suites passed **9 original + 15 new = 24 tests**, including negative cases.

## Measurements

| T1 simple document revision | B. Lightweight structured packet | 13/13 | 0 | 559 | 17 | PASS |
| T1 simple document revision | C. Graph-derived view + receipt | 13/13 | 0 | 587 | 17 | PASS |
| T2 multi-source review with approved override | A. Manual packet | 18/18 | 0 | **842** | 9 | PASS |
| T2 multi-source review with approved override | B. Lightweight structured packet | 18/18 | 0 | 900 | 21 | PASS |
| T2 multi-source review with approved override | C. Graph-derived view + receipt | 18/18 | 0 | 889 | 20 | PASS |

All six packets also had zero unrelated source-revision references, explicit no-model/no-fallback restrictions and the expected destination. These are **literal-match checks**, not token counts, semantic comprehension, model-behavior measurements or guarantees that a real launcher would inject these exact instructions.

Across the two tiny examples, total delivered payload was **1,323 bytes** for A, **1,459 bytes** for B and **1,476 bytes** for C. A was the smallest on both tasks. Neither B nor C showed a verified **correctness** advantage over A on these fixtures. C was 106 bytes larger than A for T1 and 47 bytes larger for T2. B was 78 and 58 bytes larger than A respectively.

## Adversarial controls and what they establish

The 15 new tests exercised: six-packet equality of static acceptance; genuinely distinct packet formats; source revision mismatch against frozen expected truth; duplicate rule IDs; dangling sources; experimental rule incorrectly promoted to policy; unapproved override; wrong task override; double target override; superseded text reintroduced; irrelevant source/body inserted; missing uncertainty disclosure; missing durable destination; unauthorized model route; and missing no-fallback guarantee. **All 15 passed.** The existing nine graph-fixture tests also passed.

These controls demonstrate that a small, bounded validator can detect a useful class of errors. They **do not demonstrate that a permanent graph is the only way to achieve those checks**: the comparison itself runs a common validator against the manually authored packets too.

## Preparation/maintenance overhead

A and B each used two hand-authored task Markdown packets (one file per task). C used one synthetic source/relationship fixture and an `evaluate.py` resolver/renderer that can be reused for further tasks; C also needs authoritative rule IDs, exact revisions and scoped override records maintained as inputs. The evaluator is shared test machinery, so including its bytes wholly in C's runtime cost would double-count; excluding it entirely would hide the graph implementation obligation. **Human authoring time, cost of future changes, retrieval operations, process latency and long-run maintenance burden were not measured.** No statement about a measured time/cost win is justified.

## Interpretation and proposed architectural decision

**Reject the premise that ASES needs a persisted context graph or mandatory startup document for routine task dispatch.** On this controlled evidence, task-specific manual or lightweight structured packets are *sufficient* and cheaper to represent. A practical default is:

- **A: compact manual packet** for a straightforward task with one or two clear sources and no complicated conflict.
- **B: lightweight structured task view** for a task with multiple sources, approvals, uncertainty or cross-role handoff; include an inline provenance/override receipt in the packet.
- **C: graph/typed resolver only as an optional pilot** if repeated real task failures show manual/structured preparation loses provenance, leaks superseded instructions, or fails under significant scale.

This is a **recommendation for operator review, not adopted policy**. The lack of graph superiority in a two-task static experiment is not proof that a graph would never be useful, particularly at scale or under churn.

A single well-designed **task view contract** can remain stable across all three representations. No `AGENTS.md`, `SESSION-START.md`, `SESSION-END.md`, database, daemon, CMS or dedicated resolver is mandated by the semantic topology. If some harness needs a bootstrap adapter, assess that requirement per harness, not by preserving the older document names.

## WHAT-NOT-TESTED

No model invocations; no actual agent consumption; no real repo-specific instruction loader; no measurement of effective context sent to a provider; no elapsed authoring time or cognitive error rate; no tokenizer counts; no large-scale graph changes; no stochastic selection or adversarial human packet-writing study; no production policy promotion. The coordinator authored both the cases and all three packet approaches: **shared-author bias** limits the evidence.

**Luna/pipeline status:** no Luna experiment was running or queued during this comparison. WNASES-18 is a registered but unlaunched independent pilot, with a past failed environment attempt. It does not block WNASES-22 and was not used here. The OpenCode exposure pilot WNASES-19 also remains separate.
