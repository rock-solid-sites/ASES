Independent differential oracle first reported: `rust-oracle mismatch at row 0`, accepted charge `-20` instead of `0`.

- Fix: clamp the Rust subtraction with `.max(0)` and strengthen unit test to assert `charge_cents == 0` for a covered allowance.

These were CI setup problems, distinct from the code defect.

## Remaining discriminating tests

1. Produce matched **optimized builds**, warm compilation measurements and multiple benchmark repetitions with confidence ranges. Account for toolchain/dependency setup separately.
2. Test input validation and overflows at the wire boundary, incl. malformed JSON, unrecognized fields, missing fields, integers outside signed 64-bit range and negative values. Note: Haskell uses unbounded `Integer`, Rust uses `i64`; equal wire semantics need explicit specification.
3. Test **atomic concurrent reservations, billing transitions, stale observations, delayed reports, reconciliation and crash recovery** under identical workloads.
4. Compare explicit state-machine analytical models to constraint/accounting/event approaches for *defect-finding effectiveness*; no commitment to an all-state-machine architecture or kernel-0.
5. Evaluate property-based testing and formal verification effort; then consider Pumpkin solver integration, incremental computation reuse, Tidepool-style composition and costs of Rust compilation optimizers such as Blaze.

### Build and executable measurements

All obtained in **one** GitLab-hosted Linux/amd64 shared-runner job. Toolchains: `rustc 1.99.1`, `GHC 9.0.2`. The Haskell `aeson` library was preinstalled via Debian packages; Rust's Cargo built/down­loaded the Serde dependency graph. Therefore **these cold-build numbers do not compare equivalent dependency-build or toolchain-setup costs**.

| Metric | Rust dev | Haskell -O0 | Rust release | Haskell -O2 |
|---|---:|---:|---:|---:|
| Cold source + available-deps build elapsed | 7.08 s | 0.89 s | 7.65 s | 1.17 s |
| No-change warm build elapsed | 0.02 s | 0.20 s | 0.02 s | 0.19 s |
| Build peak RSS (GNU time) | 273,900 KB | 331,188 KB | 280,204 KB | 330,636 KB |
| Executable file bytes | 6,919,016 | 17,987,320 | 597,272 | 17,929,536 |

These warm runs are **no-change builds**, not incremental rebuilding after changing code. No change-compile, cache-aware dependency comparison, Blaze effect, or compiler scalability test has yet been performed.

### Repeated end-to-end execution time

Same 12,300-case input (~3,382,813 JSON bytes), 2 warmups, 9 measured runs per executable. These measurements include process startup, JSON parsing, decision computation and JSON output, not only core admission logic.

| Statistic | Rust dev | Haskell -O0 | Rust release | Haskell -O2 |
|---|---:|---:|---:|---:|
| Median | 133.130 ms | 432.931 ms | 20.274 ms | 261.106 ms |
| p95 (9 samples) | 134.945 ms | 439.244 ms | 20.918 ms | 267.934 ms |

On this small **JSON-heavy** workload, Rust release was ~12.9× faster than Haskell -O2, but implementation/library choices and runtime allocation behavior are not controlled. This **does not justify a universal language choice**. Profile JSON parse/encode vs pure decisions, compare equivalent performance-oriented libraries, and add substantial rules/solver workloads before drawing conclusions.
