# Related-work reconciliation — bounded pilot

Experimental, not a deployed service or a replacement methodology. Implements a revision-scoped reconciliation state model for the existing task-scoped related-work convention. Scope: reviewed directional routes between existing topic/receiving checkpoints; source revision is an exact artifact identity, not a wiki edit or unrelated repository HEAD. Each observed revision remains separately addressable; an older acknowledgement cannot erase a newer pending entry. Source facts are stored once at their owner. A derived display shows outstanding revisions in the existing receiving checkpoint.

Run `node test.mjs` from this directory. The same pure functions were executed in the Chat connector orchestration environment before publication (17 assertions). No model dispatch, additional dependency, datastore or daemon. `reduce` assumes the caller has actually checked source/recipient access and applicability; an asserted boolean is not an ACL. Consultation and disposition require actual evidence; the implementation cannot prove that an LLM read a source. Adapter must re-read the specific source and section revision, perform a conditional section patch, verify readback, and retry after conflicts from fresh state. Duplicate events are no-ops; pending revisions survive interrupted delivery and independent acknowledgements. Never send private data through public paths. `mayAdvance` is a candidate guard for affected checkpoint transitions only, not an enforced native ChatGPT hook. Whole-page writes outside the adapter are not gated.

Live pilot and route binding are recorded in the existing Projektor topic-register pilot (PJDEV-6); actual uptake separately evaluated by ASES-23. Synthetic permission/error inputs test reducer behavior only, not server ACLs or concurrent backend transaction guarantees. No claim of automatic detection/notification until an execution integration is qualified.
