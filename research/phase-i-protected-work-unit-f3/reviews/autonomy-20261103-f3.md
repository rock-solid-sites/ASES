# Independent F3 L5 source/conformance review — first verdict

**Verdict: the broad claim fails.** The narrow fixed three-case grant-ceiling discriminator is implemented, but source and a policy-level counterexample show that an inactive/sealed ancestor does not deny descendant use. Current manager authority, stale ingress, and all protected routes are not established by this L5 witness. This is not a finding that its intended three scripted cases cannot pass on the original host. **Certainty:** evidence-based for the source-level ancestor counterexample; native-host enforcement not tested here.

## Evidence and limitations

1. `permissions()` intersects each ancestor's grants/latent ceiling. The use loop computes `enabled` from current ingress and **D only** (`active` and `sealed`), omitting C and Q/P activity or sealed status. In a disposable copy only, after authorized move and activation, I committed Q as `active=False, sealed=True`, keeping D active and read-granted. The original use decision returned `read: OK`, x SHA-256 `1462070e6b10a8baf625a31791cd0f4e95af638b42b1767c2aaaf8c79cdef061`, from record `record-000010.json`. The same case denied write, reflecting its remaining ceiling. This tests a deliberately constructed current state; the scripted witness does not expose a Q-seal operation, so this is a policy/state-conformance counterexample, not a demonstrated worker-triggered exploit.
2. The same policy-level harness positive control produced `read: OK`, `write: COMMITTED`, one effect (SHA-256 `8732b8a00f4332a354a08c1713b3f31278436d3c16f2befae9095e47590bbd06`). Its unsafe ceiling mutant produced `write: COMMITTED`, one effect (SHA-256 `b4ef82a3fe2424cb069551300623c175e7f8954c0e5242076f5c6446b4cea781`). This demonstrates the tested decision's discrimination, not OS isolation.
3. `manager_roundtrip` authorizes a static test credential and actor string and operates on caller-provided in-memory `st`; it does not itself load the published current selector or establish fresh management authority. Both socket ends and the credential live in the runner. Under the declared single trusted holder/no-external-writer and scripted-serial profile this is a simulation, not proof that stale management credentials or retained old routes are fenced. The positive activation branch also directly mutates and commits state rather than exercising `manager_roundtrip`. Activation tests all units inactive but does not test that they are sealed. Move publishes C's parent and D's unchanged child relationship in a single state image followed by a separate activation image; this is evidence of one whole published record under the local atomic-replace premise, not a crash, durability, concurrency, or rollback proof.
4. The L5 protected-use path opens a fresh worker with `close_fds=True`, `pass_fds=(child.fileno(),)` plus inherited standard streams; no protected file descriptor is intentionally handed over. The selected socket is serviced for exactly two requests and current ingress is a fixed string checked against state, not authenticated against the particular socket. This L5 code does not attempt an old retained socket after replacement, inherited protected FD, alias, SCM_RIGHTS, descendant, network, or concurrent writer bypass. L1's Landlock permits library paths and denies handled filesystem rights elsewhere but Landlock does not revoke a previously opened descriptor. The L0 assumptions exclude or leave untested these routes; do not elevate this to all-route mediation.
