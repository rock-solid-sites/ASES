# Agent launch and route selection

Resolve **controller**, **execution host**, **launcher**, **target provider/model**, **permissions**, **source revision**, **resource/time budget** and **durable result location** before launch. Model identity belongs in trusted caller-side settings, not in the recipient's self-identification prompt. Never silently substitute models or execution hosts.

## ChatGPT coordination launch convention (active)

**No inferred model selection, no default models, no delegated model selection.** Before authoring a manual-launch task or calling a tool/workflow that can invoke any model, the coordinator must establish the exact caller-side `provider/model` ID, execution host, entitlement/billing route, and `fallback: none`. Display a compact launch declaration in chat (one line is enough), for example: `OpenCode Go subscription | <exact catalog-verified opencode-go/model> | host verified | paid API: forbidden | fallback: none`. Do not place model choice in the receiving agent's discretion.

**OpenCode harness versus model provider:** OpenCode is a launcher capable of selecting several separately billed providers. Its **Go subscription** route permits only eligible, verified `opencode-go/...` models; its **Zen free** route permits only exact, verified zero-price `opencode/...` entries. Zen also has paid models. Other providers used *through OpenCode* (for example NVIDIA, OpenRouter, Vercel) are **not categorically prohibited**: they require explicit approval of the exact provider/model/account/funding route and a bounded permitted allowance or spend. A working API key and available catalog do not authorize them. Unknown model, billing tier, limits, balance or route = **stop before invocation**. Never choose paid Zen, an unapproved Go model or any different provider/model as an automatic fallback. This restriction does not ban the independently approved Phoenix Grove reviewer route.

**Mixed free/paid model catalogs (general rule, not a provider ban):** OpenCode (Go/Zen), OpenRouter, Vercel AI Gateway and similar services may list **both free and chargeable models in the same provider catalog**. A model being offered by a provider, free-sounding name, successful authentication, or available balance is *not* authorization to use it. For each dispatch, pin the **exact provider + model ID + endpoint/account + billing source/tier** and verify that **this particular route** is currently approved and inside the operator's permitted cost and quota. A provider can be allowed for one specific free/subscription model yet denied for another paid model. Free offers can expire or be limited: unknown price, entitlement, fallback, credits or overage = **stop before invoking the model**. Model aliases, automatic router choices, optional paid upgrades and cross-provider substitutions require separate explicit approval; do not silently substitute a "similar" or "available" model. OpenRouter and Vercel are examples of mixed catalogs here, **neither blanket-banned nor blanket-authorized** by this paragraph. Historical account balances or credentials do not grant a spend budget.

**Funding / entitlement types (select explicitly, never infer from provider):**

| Funding mode | What it covers | Mandatory verification and stop condition |
| --- | --- | --- |
| **Subscription allowance** | Included usage for specific products/models, within plan limits | Confirm account, eligible model/route and remaining allowance; no conversion to separate API billing or paid overage. ChatGPT Plus/Codex, OpenCode Go and some other plans are distinct subscription products. |
| **Purchased/prepaid API credits** | User-funded balance debited by metered API calls | May be used only if the operator has authorized this account, model and a bounded credit spend. Check available balance and cost/units; no auto top-up or postpaid charge. Existing purchased credits are **not the same as free credits**. |
| **Promotional/free API credits** | Provider-funded balance or promotional grant that offsets otherwise chargeable usage | Verify eligible models, remaining balance, expiration, reset and what happens after depletion. Stop rather than silently debit purchased credits, switch tiers or charge a payment method. |
| **Free model / free-tier inference** | A specified model/endpoint has verified zero monetary price or an eligible free-call quota, possibly with rate/usage limits | Check the exact model, provider route, request meters, present eligibility and throttling. A free model is **not** a cash balance, and an API's free quota can be exhausted even when no payment is due. |

These categories are **independent dimensions, not exclusive provider labels**. A provider can simultaneously offer a subscription, a prepaid wallet, free credits and zero-price models; the same model can be charged differently across accounts, gateways or routes. An API key, catalog listing or advertised free tier does not establish which funding pool a request will debit. For mixed funding, name the **one intended funding source**, verify priority and overflow behavior, and forbid automatic substitution between pools. Record unknown billing as unknown, never as zero. Other execution costs (Actions minutes, cloud compute, storage) remain separate meters.

**Examples requiring account-specific verification:** NVIDIA hosted NIM developer/prototyping access may be free but has eligibility and limits; OpenRouter has both a paid API-credit wallet and separately designated free-model variants; Vercel AI Gateway has free-credit and purchased-credit tiers with model eligibility differences. None of these examples confirms this user's current balance, exact model entitlement or permission to incur charges. See `docs/research/Resource Solver Specification Reconciliation 2026-11-02.md` §§2–4 and `research/provider-registry/known_accounts_v1.json` for the existing **experimental**, account-scoped source and historical registration claims; do not create a second account registry or misrepresent historical balances as live.

**Compact caller-side launch declaration:** `host | exact provider/model/endpoint | account or approved route | funding_mode | verified balance/allowance + as-of | maximum authorized use/spend | overflow/top-up/fallback: disabled | evidence destination`. The model/provider route and funding mode must both be verified; a user may approve a bounded purchased-credit or promotional-credit use, while an unknown or unauthorized chargeable route must stop. Declaring a model "free" is not a substitute for checking its actual provider-specific meters.

**Independent Phoenix Grove route (separate authorization):** Phoenix Grove via a directly configured **Codex/PGS2 provider** is an allowed, separately authorized execution path; it is **not an OpenCode Go or Zen model selection**. Do not reject it because a model is absent from the OpenCode subscription catalog. To dispatch, establish explicit operator authorization for that invocation/allowance, pin the actual `pgs2` provider, exact PGS model ID, Codex version, host, bounded runtime/spend, available secret and `fallback: none`. Prefer a known verified route and retain provider usage/billing as unknown unless measured. A previous successful PGS call proves technical reachability, not unlimited future allowance. **Do not infer that a restriction on unapproved OpenCode models also forbids Phoenix Grove.** Example: `Phoenix Grove PGS2 | Codex 0.169.0 | deepseek-v4.1-flash-1017 | GitHub Actions | scoped review authorized | fallback: none`.

**Luna route exclusion (cost rule):** GPT-6 Luna is reserved for the operator's existing **ChatGPT Plus/Codex subscription**. **Do not select `opencode-go/gpt-6-luna` or any other OpenCode, Go, Zen, API or third-party Luna route**, even if the model appears in a catalog or succeeds on another provider. A Codex Cloud Luna task is permitted only when the operator's authenticated subscription, chosen model, and execution environment are confirmed; otherwise report the blocker and do non-model work. Never substitute OpenCode Go Luna for an unavailable Codex Cloud environment. ChatGPT subscription access does not authorize an OpenAI API call.

**Other model execution:** use OpenCode for **non-Luna** models on an explicitly approved route: eligible Go subscription, verified zero-price Zen, or another named provider/model/account funded by an authorized subscription, promotional/free credit, purchased API-credit budget or verified free tier. **Other approved launchers/providers**, including Codex with PGS2, have their own route-specific authorization and billing gates. A familiar model name on a different gateway/account does not imply identical entitlement, price or quota.

**Stop rule:** Never use automatic model fallback, unapproved overages/Extra Usage, unauthorized API spending, inferred substitutes, or a default model to work around a missing route. Authorized purchased credits are *not* prohibited; exceeding the approved credit budget or switching to postpaid billing is. If the allowed exact model cannot be verified or launched, report the blocked route and continue only with non-model work. Do not run a model just to test the validity of model selection. The same rule applies to manual launch prompts, delegated agents, GitHub Actions recipes and diagnostic probes. The coordinator owns model choice; the receiving agent must not be asked to choose it.

**Scope and assurance:** This is a conversation/dispatch procedure, not a claimed universal mechanical enforcement boundary. Existing picker-label plugins and historical Crosslink Task gates do not enforce it. A model-facing prohibition is weaker than host-side credential restrictions; do not claim an agent cannot bypass a convention. Future centralized admission control belongs with the separately planned Resource Solver.

For independent reviews, use `skills/current/review-launch/SKILL.md` and the current `ases-plugins` reviewer recipe. GitHub Actions is proven for short, bounded one-shot reviews; Codespaces/Modal are candidates for deep investigations, with workload-specific readiness to verify.

The old IT3812/VPS and Crosslink environment mentioned in `docs/methodology/Agent Model Launch Routes.md` is **historical** and must not be assumed connected or executable. Use that document only for model-provider compatibility details explicitly corroborated in current runs. Phoenix Grove reviewer routes and credentials are documented separately; a successful prior test establishes feasibility, while each new PGS2 review needs explicit scoped authorization and limits **independent of the Go/free-Zen restriction**.

Check the actual connected tools before claiming a remote launch can happen. Prefer the smallest approved test. On missing tool, route, account, secret or authorisation, report the precise blocker; no silent fallback. For long-running tasks, preserve durable commits/position records and validate progress rather than treating a live process as proof of work.
