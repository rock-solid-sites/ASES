# Bounded inventory and disposition check

**Verdict: supported for this disposable store and process-loss profile.** The actual directory inventory prevented logical removal while unregistered candidate bytes survived a killed, uncommitted writer. The explicitly weakened catalog-only comparator admitted logical removal with the same kind of surviving bytes. The interrupted logical-disposition case recovered the remaining candidate and finished through explicit disposition. This is evidence for the selected discriminator, not full L6 or T13/T23 closure.

**Basis and certainty.** The source-first prediction was saved before the one probe run; the executable source is the committed baseline `b5b91fcb017c31ffec697f357228e3a3eef25313`, and raw source hashes match that commit. The independent audit reads the recorded JSON and wire frames, checks source identity, bytes, process ordering, SQL traces, responses, snapshots and controls without importing the producer checker. The producer checker ran afterward and also reported support. Findings are evidence-based for these exercised histories and depend on the instrumented process and snapshots reporting accurately.

- In each orphan case the gate reported an open transaction, one local row, and SQL INSERT after BEGIN IMMEDIATE without COMMIT; source writes, flushes and fsyncs z before the gate. After SIGKILL and reap, independent catalog snapshots showed zero rows and exact z bytes on disk, classified as unknown. The reference removal queried live catalog rows and denied with z in its inventory, retaining the live sealed unresolved unit and bytes. The explicit catalog-only mutation committed logical removal while z and the directory survived; its own response says the physical boundary was not removed. It is an experimental mutation, not an observed defect in L5.
- Both x and z received commit responses, and a read returned exact x. The disposition gate showed UPDATE and COMMIT, no open transaction, before unlink and reply. After kill/reap, x was logically disposed, z remained live, and both exact files remained. A fresh child given only the root reconstructed the sealed current records; mediated x read was denied, z read returned exact bytes, and removal was denied. Cleanup removed x while preserving z; removal was still denied until explicit z disposition, after which empty-directory removal succeeded. A separately empty sealed unit also removed successfully.
- Eight distinct child processes were observed, at most one active at a time; recorded elapsed time was 0.305 seconds. The source sets a 256 MiB address-space limit per process and three-second frame waits. Missing-recovery and contradictory-inventory mutations were rejected by the independent audit; the producer checker independently classified its corresponding controls incomplete and violation.

**ACK qualification.** The harness collected the disposition gate and then killed and reaped the child, recording no response among its collected events. Source places the response after the blocked gate. The harness does not separately drain the transport to EOF, so the record alone does not prove a transport-level absence of a late response. The secondary producer check's unqualified “no success ACK” wording must be read with this limitation.

**Not tested.** This flat enclosing-root inventory assumes all durable objects are inside that root and all writers cooperate with the lock; management is trusted. It does not establish native confinement, credentials, host-namespace exposure, secure erasure of raw handles/backups, physical power-loss behavior, atomicity across logical removal and rmdir, concurrent dependent creation/removal, scratch teardown, or generic L6/T13/T23/F3/F4 closure. The source gate identifies the fsync path; no independent syscall trace was captured. Current sealed unresolved material is not an empty successful recovery. Disposed logical references are mediated through this store; raw filesystem access remains outside the profile.
