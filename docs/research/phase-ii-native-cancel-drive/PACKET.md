# Native cancellation driver — bounded packet

ASES-4 priority D, extending existing resource-drive -> resource-session -> trusted Unix gateway -> retained Child -> exact Store exit -> separate finalization. Depend on completed #40 plus #39/#33/#32/#31/#29; base 27e258e3. No new execution model or server interface.

WHY: the existing driver integrates launch/exit/finalize, while cancellation still requires callers to join stop and finalization manually. A thin explicit cancel mode can enforce the same exit-evidence prerequisite without launching or retrying unknown work.
WHAT: add `resource-drive cancel SOCKET JOB LAUNCH STOP_ID GRACE_MS`, preserving existing launch arguments/output. Explicit cancel chooses semantic outcome cancelled; never derive it from exit status. Validate selectors before any connection, grace 1..2000. Reuse fixed sibling resource-session and existing bounded capture/invoke helpers. Issue stop-graceful exactly once; require matching job, launch, stop, mode term_then_kill, exact grace, replayed bool and supported state/exit. Only exit_observed with valid exit can trigger exactly one finalize cancelled. Unknown/unsupported/lost/error replies return phase-aware recovery immediately, no launch/poll/retry/automatic repair. Finalize reply must match selectors/outcome and CLOSED/CLOSED_REPLAY. Success outcome finalized + selected_outcome cancelled, action cancel. Recovery preserves stop selector, last_action stop-graceful/finalize, client status/reply and confirmed observations. No claim that an error means no effect or held capacity.
HOW CERTAIN: hypothesis requiring actual gateway/Store/Child tests and a transport proxy that forwards a real operation then loses its reply. Existing client has bounded waits; this is not a hard wall quiescence guarantee, and a server may keep processing after client loss.
WHAT-NOT-TESTED: host/power loss, arbitrary process trees or programs, provider workloads, hostile same-UID exclusion, universal hard wall cancellation. Cold controller cannot adopt an old PID and must remain unknown.

Evidence: cooperative cleanup and forced fallback via bounded fixed worker; stop reply loss after actual recorded stop/exit => recovery at stop with no finalize; finalize reply loss after actual commit => recovery at finalize with Store CLOSED/capacity released; cold custody loss => unknown/no signal/new dispatch/finalization; conflicting stop selector => received servererror/no automatic retry; invalid input rejected before connection. Preserve exact request/replies, worker markers, raw lifecycle events/balances and source hashes. Existing launch driver/native cooperative stop regressions once. One Cargo build at a time using existing shared target; commit frequently, push isolated draft branch, no main merge/deploy, independent CI/review/backup work.
