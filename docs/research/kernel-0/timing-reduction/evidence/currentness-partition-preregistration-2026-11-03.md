# Currentness and observation partition — preregistration

Starting point `2244e237e`; frozen oracle and catalog. Existing `flight_explore` has separate invoke/observe/resolve phases but its resolve replaces a whole State in one event; it cannot expose a partially published state. Test a complementary independently enumerated schedule partition, with logical candidate preparation distinct from publication, retaining the explicit boundary that an authoritative whole-oracle commitment is one abstract event. It does not assume all internal work happens together and does not model physical atomicity or split authoritative publication.

Fixture: independent profile, initial a0 rights 7 and data `(0,0)`; worker `set(x,1)` and manager `restrict(a0,0)` are catalog proposals. Events: `read` copies the worker's current state; `prepare` computes its candidate from that view; `revoke_prepare` is invisible; `revoke_commit` resolves the restriction with the current oracle; `monitor` observes the current authoritative state; `write_resolve` is the worker resolution. Preserve within-operation order `read < prepare < write_resolve`, `revoke_prepare < revoke_commit < monitor < write_resolve`. Enumerate every permutation of these six events satisfying those edges, partitioned by whether `read` precedes `revoke_commit`. Compare a current-resolution control against the inherited stale-view/merge style mutation. Each monitor read is authoritative. Check proposed outcomes, final state and monitor state against all serial orders of restriction, write and monitor with `restrict < monitor`; the write overlaps them and may linearize on either side. A matching witness must preserve each outcome, monitor view and final whole state.

Predictions: every schedule has a witness under current resolution; stale resolution has no witness when it captures pre-revocation rights and publishes after the monitor, but matches when it reads after revocation. `prepare` and `revoke_prepare` are deliberately non-authoritative, so this fixture tests coherent *whole* observations/currentness and interacting commitments, not field-torn reads or split authoritative commitment. Oracle operations share the same frozen model; the separate serial permutation enumerator is independent algorithmically, not an independent semantic implementation. State caps 1,000, 10 s, 1 GiB, explicit total schedule cap, report exhaustive schedule counts by partition, traversed event counts, candidate history counts, failures, bounds and exact truncation cursor. No global or physical claim.
