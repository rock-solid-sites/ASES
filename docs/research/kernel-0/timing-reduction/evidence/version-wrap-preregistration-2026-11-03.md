Starting point `9471fa726`. Test the version-no-wrap assumption exposed by the previous result. Initial `(0,0)` changes by two whole commits to `(1,0)`, then `(1,1)`; each commit increments the version by two, atomically with state. Reader samples version at begin/end and accepts equal even samples, reading both fields separately between them. Enumerate both field read orders and all interleavings of `commit1 < commit2` with `begin < read1 < read2 < end` (30 per mode). Compare unbounded integer version with modulo-4 version, each starting at 0; calculate eligible whole-state cuts inside the read interval independently. Predict unbounded validation has no accepted incoherent observations, while modulo-4 permits `(0,1)` accepted when two commits wrap between samples. Also report any equal-version acceptance whose value happens to be coherent, since detecting wrap and detecting incoherence differ. Rejections withhold values; no retry or progress claim.

Bounds 60 cases, 420 per-case cuts, 10 s, 1 GiB; include case and cut truncation controls and raw traces. This toy test covers exactly two commits and does not establish a version-width requirement or real memory ordering.
