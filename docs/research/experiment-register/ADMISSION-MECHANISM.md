# Minimal experiment admission — integration candidate (2026-11-28)

**Status: experimental reference, not active policy or a deployed security boundary.** ASES-28 / WNASES-37. The operator approved consolidation after the retrospective and prospective pilots, not global enforcement. No new service, database, model invocation or duplicate Resource Solver/ASES-13 work.

## 1. What the evidence changes

- [Retrospective](PILOT-RESULTS.md): four delivered reviews declined proposals as written; the later expansion was correctly challenged, but the early useful mitigation was also challenged and its justification depended on the exact parent decision. Preserve classification, causality, mitigation and operational assurance as distinct decisions. Do not confuse review rejection with scientific correctness.
- [OP-01 receipt](evidence/op-01-r1-excerpt-terminal.json) and [evaluation](https://github.com/rock-solid-sites/ASES/blob/b55f64df3cb6990ada7f26e58e9f45e0e6739ac2/docs/research/knowledge-index/OP-01-R1-RESULTS.md): source inspection narrowed an invalid cross-repository scope before inference. The full review exhausted its 8192-token cap without answer; a 67% shorter decision excerpt yielded a substantive recommendation but an IMPLEMENT/ADMIT semantic conflict. Operator manually admitted one experiment. The result supported a scoped DISCARD recommendation. Two review attempts spent 11752 completion tokens; benchmark computation 61.711 ms, CI 34.405 s, no inference. Neither a general reduction in review cost nor net cost-effectiveness has been established.
- Consequently: source qualification first; one small review of the decision (when needed), separate fixture qualification, explicit verdict/action semantics, no automatic reruns of failed reviews, no review per deterministic test, and no automatic continuation after a parent decision is answered. Cheap work must not incur an expensive ritual.

## 2. Minimal operational path

1. **Identify the decision.** Reuse the parent investigation/decision register; state the objective, unresolved uncertainty and distinct positive/negative/inconclusive dispositions. Exploratory research may have its own bounded learning objective and a decision about whether to pursue it; never manufacture a blocking dependency.
2. **Qualify from existing evidence.** Check pinned source/receipts, actual object/authority, privacy, feasibility, cheaper discriminators, controls and limits. Record READY, REUSE (already answered), IMPLEMENT (existing evidence sufficient to implement), or BLOCKED. Non-READY cannot dispatch this experiment. Resolve the parent decision or route the blocker, do not generate an experiment to avoid making the decision.
3. **Freeze the smallest plan and classify review need.** Pin exact plan bytes, SHA-256, parent/decision identity and approved limits. Use a decision-only excerpt for reviewers when fixture detail is not needed; bind the excerpt and exact full-plan revision in the receipt. The owner/controller, not the proposing agent, classifies the review policy. Use risk and expected information value, not a universal time or token threshold.
4. **Review proportionately.** A new consequential investigation or hypothesis, material extension, contested continue/implement decision, expensive/irreversible or externally consequential trial warrants independent admission review. A routine deterministic check, replay, red/green verification or approved retry within an already admitted matrix does not need a fresh model review. A genuinely small, local, reversible decision experiment can take the deterministic fast path only under explicit owner-approved risk classification, not merely because a proposer labels it cheap. Existing execution/permissions/billing rules always apply; this carve-out is a draft choice requiring adoption before general use. Unknown review policy blocks.
5. **Authorize exact revision.** Review recommendation is not authority. Owner/controller resolves conflicts without vote-shopping; record explicit manual review exception and reason if appropriate. Preserve the raw evidence and never rewrite the reviewer label. The exception waives only the review condition, not source/identity/stop/budget/permission checks. Bind authority to the full plan revision, not a mutable branch or excerpt alone.
6. **Dispatch via existing execution boundary.** Run the reference predicate only on verified controller facts, then atomically claim the exact dispatch identity and reserve the bounded aggregate envelope through the existing execution/Resource Solver mechanisms. If state changes before claim, revalidate; never infer runtime authorization from the predicate. Route-specific provider, account, privacy, token, overflow, cancellation and reconciliation checks remain separate and mandatory.
7. **Settle and stop.** Append terminal observations, including failed/partial/unknown results and actual resource receipts. Re-evaluate parent decision and stop rule before another proposal. Record IMPLEMENT / CONTINUE (new registered uncertainty) / CLOSE / BLOCK / DEFER. A revision changes the question, inputs, scope, outcome meaning, envelope or stop criteria; it requires fresh admission. Reusing a reviewed matrix's already authorized slots does not create a fresh plan.

A review need is assessed once per frozen experiment or matrix, not per invocation. No extra model call solely to satisfy a gate that does not alter the decision. No universal automatic approval for "free" models or local compute. Record review and preparation costs separately from experiment costs.

## 3. Review output contract

Return a short, source-linked recommendation, preserving grounds, cheapest adequate alternative, action detail and uncertainty, with a typed action:

| Verdict | Required action code | Meaning |
| --- | --- | --- |
| ACCEPT | ADMIT | Experiment may be worth doing as written; still requires authorization |
| REDUCE | REVISE | Current revision blocked; narrow/revise or explicit owner disposition |
| REUSE | USE_EVIDENCE | Answer from existing evidence; no proposed run |
| IMPLEMENT | TRANSFER | Hand off to named implementation task; do not run proposed experiment |
| DEFER | DEFER | Separate or postpone question; no current dispatch |
| REJECT | CLOSE | Close proposed experiment with reason |

Expected review record: exact full revision, optional excerpt hash, trusted reviewer family/route and independence, terminal status, raw response and receipt, verdict, action, grounds, cheaper alternative, action detail, uncertainty. Validate exact response custody and schema, then separately compare enum/action and human-readable grounds/action detail. The reference predicate checks the typed pair and a **trusted controller's recorded meaning check**. It cannot interpret arbitrary natural-language contradictions. The OP-01 raw IMPLEMENT with prose "run once" remains a conflict even if a future model supplies TRANSFER as a structured code. Missing, stale, failed, same-family/unverified or semantically conflicting required review is not ACCEPT. Manual exception is an explicit owner decision, not inferred from a model recommendation or a hidden model substitution. No retry solely to seek a different verdict.

## 4. Reference contract (pure, not authoritative)

[Reference implementation](reference/admission-v1.mjs), [deterministic contract tests](reference/test-admission-v1.mjs), [verification receipt](reference/verification.json). The JavaScript module is a disposable reference predicate because its exact function body could be executed and persisted through the available Chat JavaScript tool, not a technology decision for ASES. It takes a plan object parsed from frozen verified bytes and a separately supplied trusted controller snapshot.

**Plan:** experiment_id, decision_id, parent, objective, kind (DECISION or EXPLORATORY), prior_search, evidence (references, possibly empty after a documented search), uncertainty, least_method, scope (inputs/controls/exclusions), outcomes (positive, negative, inconclusive), limits, stop, evidence_home. All text fields nonempty; positive/negative actions must not be identical text. This last check detects only obvious vacuity, not semantic decision value.

Limits use nonnegative safe integers: runs, wall_seconds, model_requests, completion_tokens, cash_microusd. Runs and wall_seconds positive, completion token budget required with model requests and zero otherwise. This is a reference for text-generation/local experiments, not a general provider accounting schema. Aggregate compute, RAM, storage, provider allowance, exact model/account, input tokens, other effects and units remain managed by the existing resource/permission mechanisms; a plan with zero cash is not automatically free or entitled.

**Trusted controller snapshot:** verified_revision (SHA-256 of exact plan bytes, computed outside this predicate), active_revision, experiment_id, decision_id, parent, state=OPEN, stop_reached=false; qualification {revision,status,receipt}; review_policy {revision,required,reason,receipt}; optional review {revision,status,receipt,independent,verdict,action,meaning_checked}; authority {revision,experiment_id,decision_id,status=AUTHORIZED,mode=NORMAL or MANUAL_REVIEW_EXCEPTION,receipt,reason for exception}; dispatch {id,revision,claim_state=UNCLAIMED,ledger_receipt,request,remaining}. The request and remaining use the plan limit keys. The reference checks shape, identity, revision, state, stopping, qualification, policy, authority, review pair and envelope bounds. Missing or ambiguous verified facts block. A stale or malformed attempted review is not silently ignored even on the fast path. An explicit exception can waive a known missing/incomplete/adverse/conflicting review; it cannot waive qualification or resource checks.

**Output:** BLOCK with stable reason, or ELIGIBLE_FOR_ATOMIC_CLAIM with exact identity, revision, dispatch ID, request and review disposition. This result never launches anything, consumes no allowance, and is not an execution permit. Controller must authenticate source, authorize effects, compute/verify hash against parsed bytes, validate receipt content and integrity, determine policy/meaning from real evidence, bind controller fields to one current authoritative snapshot, and atomically claim/settle through the existing ledger. A caller can fabricate every string or boolean in this object; the predicate is not a trust boundary on its own. No durable state, signature, freshness or CAS implementation in this module. A repeated pure evaluation can return eligible repeatedly; actual claim/replay protection belongs to the atomic existing boundary. Do not integrate as a standalone gateway.

## 5. Ownership and adoption boundary

- **Projektor / ASES-28** owns methodology and eventual adoption; the existing parent issue owns scientific/commercial decision. Work Notes templates and task checkpoint are operational entry points. Git holds exact frozen registration and append-only receipts. Do not clone the narrative into every surface.
- **ASES-13** owns reusable reviewer launch, authorization and raw evidence custody; no separate reviewer service here. Current agent-launch/review-launch procedures still apply. Pass only the decision excerpt where sufficient, preserve full-plan binding. Never dispatch from reviewer output.
- **Resource Solver / existing execution boundary** owns current policy, authorization, atomic resource reservation, per-dispatch identity, durable settlement and cancellation. Its [snapshot gate](../../../research/resource-solver/snapshot_gate_v1.py) and [allowance ledger](../../../research/resource-solver/allowance_admission_v2.py) are experimental process-local references, not proof of production enforcement. Integrate the eligibility predicate only once the relevant authoritative boundary can supply and atomically verify current facts. Do not create another ledger or import research code into Kernel-0.
- **Validation:** 36/36 deterministic contract checks against the actual reference predicate; deliberately permissive stub passes 3/36, fails 33/36. Exact tested function bodies serialized and verified by Git readback. Node module import or clean-checkout CI has not been exercised. No new model calls, no runtime integration, no claims of scientific validity or enforcement. Unit verification is routine engineering, not another experiment to justify the register.

**Proposed disposition:** accept the consolidated draft for owner review; keep current skills and dispatch behavior unchanged until explicitly adopted. If adopted, add a short pointer to the canonical method and wire a single trusted admission check at the existing boundary, with real stale-revision/duplicate-claim negative tests at that boundary. No global hard gate until authority, atomic claim, receipt authenticity, revocation and existing procedure compatibility are verified. If the overhead is disproportionate, keep the register and targeted review as a procedural aid rather than build a service.
