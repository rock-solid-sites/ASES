# Integrated cold continuation, current admission and retained outcomes

Frozen 2026-11-10. Source candidates: admission `671ecc09`, retry `16e6460f`,
composed return-boundary fix `0e724a6c`, cold activation `4485a834`.
This is the next bounded integration check, not a general execution engine.

## One coherent effect interpretation

Retain three independent distinctions in one native process history:

1. New effect: native flat F4 authority and cold activation, plus exact current
   F1 accepted pair/L5 selected path/L6 liveness at local append.
2. Historical result lookup: exact previously accepted request identity, retained
   journal event, and fresh exact witness cut. No append and no new permission.
3. Cold continuation: preserve all accepted journal bytes, seal new use during
   each recovery, then require native replacement and native activation in that
   boot. Replacement and activation retain their separate commitments.

An old accepted effect may remain observable while new admission is sealed or
its source later changes. A new ID may not bypass either cold sealing or the
source guards. A new F4 version does not manufacture new F1/L5/L6 authority.
Unknown publication still retains local outcome and refuses unsupported retry.

## Minimal reuse

Export the already tested cold wrapper as `state_type(original, recover: bool)`
without changing behavior; its old CLI invokes the factory. Verify its existing
native probe after this small extraction. The integrated CLI uses cold state
over RetryState as the base inside the existing admission hook and original
receipt-aware cut state. Preserve the composed outer outcome wrapper. No second
journal, identity table, authority primitive, observer or scheduler.

All code stays isolated on this research branch. Original source and prior
candidate branches remain unchanged. Disposable Python integration reuses real
managed append/fsync, witness CAS, source operations and cold replay. Test-only
import/root mapping, participating writers, trusted current storage and honest
live witness remain explicit premises. This is not physical-source exclusion,
global lifecycle removal, remote cancellation or external exactly-once delivery.

## Deciding native histories

- Accept original id A before loss; suppress its real publication reply. Kill
  and reap sink, cold recover same journal/witness: A lookup succeeds with zero
  append, but new id B denies while sealed. Activate-only denies, then native
  replacement/activation permits B when all source guards still hold. Retained
  A remains an original-version observation, not a recertified new effect.
- Native F1 accepts a different same-byte evidence world (or native L6 removes
  x) after A. Cold startup/activation never restores the old source assertion:
  A historical observation may succeed but new ID under old source evidence
  denies unchanged even with the fresh F4 version.
- Kill between replacement and activation, cold restart again: retained-version
  activate-only denies, another fresh replacement required; useful continuation
  follows with live valid sources.
- Actual witness rejection: same-ID lookup remains unresolved with prior local
  sequence and new_local_effect=false; known payload conflict is decided without
  remote calls; cold divergent cut refuses.
- Old flat version with new ID cannot act after replacement; intentionally
  supplied new bearer token still has no physical-source identity guarantee.

Check original event IDs/payload bytes/certificates, exact append counts, real
source mutation, witness roots/nonces/cuts, and old/new versions independently.
Use altered controls for cold-seal bypass, historical/new-effect conflation and
fabricated current source. Preserve any integration failure before correction.
