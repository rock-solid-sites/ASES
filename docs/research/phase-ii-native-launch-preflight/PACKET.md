# Native launch preflight — frozen bounded packet

Research implementation on ASES-4 priority D; base fbf5cea6 (draft #39), retaining #29/#31/#32/#33 native launch, resume, stop and exact termination behavior. Rust, existing local gateway and Store, no independent execution model.

WHY: known missing/non-executable program or unusable working directory currently consumes a one-use launch intent before spawn. Read-only checks can reject these before intent while retaining conservative unknown outcomes after intent.
WHAT: only a stored AUTHORIZED job receives filesystem preflight immediately before existing Store.begin_launch arbitration. Check fixed trusted profile program regular/executable and cwd directory/searchable with effective-credential access semantics. Do not put filesystem checks in profile.validate, startup, scope checks, observation, replay, poll or stop. No catalog/profile registry, schema, client inputs or wire operations. Replays skip preflight and retain one-use dispatch semantics.
HOW CERTAIN: implementation hypothesis, requires native gateway/client and actual Store evidence. Preflight is not atomic with spawn and cannot guarantee exec success. Competing controllers remain governed by Store, not the preflight snapshot. A received error is not global proof of no effect.
WHAT-NOT-TESTED: all loader failures, filesystem changes in the check/spawn interval, host compromise, power loss and universal confinement. A valid executable script with an absent interpreter discriminates post-intent ENOENT from preflight failure; it must remain LAUNCHING/unknown with capacity held.

Acceptance: missing program, non-executable regular file and missing/non-directory cwd fail with AUTHORIZED/no intent, repair and same-job retry succeeds once. Actual retained sleep Child remains replayable/observable/stoppable after its temporary executable is unlinked; no second dispatch. Genuine post-intent loader error preserves unknown. Update old missing-program expectations in native gateway/client tests, preserving other assertions. Run focused new tests, affected gateway/client/driver targets and five identity-lifetime tests once, capture commands/results/source hashes. No independent review/CI work.
