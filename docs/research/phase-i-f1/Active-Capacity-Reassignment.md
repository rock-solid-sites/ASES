# Active capacity reassignment after loss — preregistration

The F1 capacity-one fixture conserves a single reservation and separately records one consumption; it lacks reassignment and completion. The two-unit extension tests competing admissions but not in-flight use after a reservation changes hands. Work Unit H says sealing does not necessarily terminate internal computation, and C3 requires resource constraints; this fixture chooses a specific safety policy: one shared unit cannot concurrently support two active consumers. This is a bounded consumer policy, not a general claim that all resource grants require quiescence or that abstract consumption is universally instantaneous.

Start with the inherited F1 reference state and reserve its one unit for S. Prepare a reassignment from S to C while there is no active use; then S consumes/starts a bounded use via inherited `consume_capacity`, before abstract stop/recover. S's use survives stop by a stipulated failure profile; it is independently observed, not inferred from current reservation. At recovered reassignment, the reference checks that S has no active use and refuses while it does. The unsafe mutation uses the earlier no-active-use prepare snapshot, changes the reservation to C, and then allows C to consume via the inherited consume guard. A separate observer counts real active uses and flags two active uses against one unit. The reference positive control ends S use after recovery, then performs the same reassignment and C use with one active user. A quiet positive control reassigns with no S consumption. All actions use serialized abstract steps; the check and reassignment are stipulated atomic, not enforced by a host. Use inherited F1 stop/recovery, reserve and consumption checks; an explicitly local `replace` operation implements the missing release/reassignment and completing the finite use resets its consumed flag. These fixture-only operations are not asserted to exist in F1 or to be canonical policies.

Exactly four fixed histories: hazard reference, hazard stale-snapshot mutant, completion-then-reassign reference, and quiet reference; no graph search. Record all F1/wrapper outcomes, count transitions, state and independent active-use violations at every step, output/hash and 30-second timeout. Invariant: at most one active consumer, and while active its owner is the reservation holder. Independent active-use observations and completion, trusted capacity, manager authorization, preserved use across stop, current allocation state and serialized transitions are premises. No physical CPU/memory measurements, process execution, enforced cancellation, concurrent scheduling, crash persistence of usage, host confinement, arbitrary resource lifetimes or general allocator conformance is tested. This distinguishes allocation change from termination of a continuing dependent use; it does not decide whether a specific real resource can safely be moved while work is active. C3/C5 and Work Unit B/H are only narrow selected-policy illustrations; F1 and F5 remain incomplete.
