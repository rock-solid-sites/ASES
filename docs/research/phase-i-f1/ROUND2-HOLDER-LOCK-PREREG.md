# Concrete sole-holder guard, retained descriptor and lock-object identity

Highest affordable discriminator for F2 T20/F3 single-holder premise without unavailable Landlock: put a Linux advisory flock guard before the existing real SQLite holder service, then exercise actual holder request/ACK paths. This is a bounded candidate, not adopted architecture or native Work Unit confinement.

Three independent disposable stores/schedules. (1) A ready; B nonblocking activation must refuse, including while A is SIGSTOPped; A resumes and accepts x, then SIGKILL/reap A; B can activate, cold-read x and accept y. (2) A deliberately transfers its lock descriptor using SCM_RIGHTS to another supervisor-owned process. A dies/reaped, B must still refuse while that descriptor remains; release/reap descriptor keeper, then B activates. (3) Unsafe lock-identity control: trusted fixture unlinks/recreates lock pathname while A remains ready; B can lock new inode, both services can ACK supported writes. This should expose dependence on one stable protected lock object, not a defect of flock under its own same-object semantics.

Use unchanged kernel0_recovery_service.serve/Boundary/Store with trusted one-lane association context0; wrapper only obtains guard first. Existing setup supplies established rights7. Record lock device/inode, guard results/PIDs, actual request/reply/recovery, syscall return, stops/continues/kills/reaps, FD-transfer receive/close, and raw command/environment/source hashes. No false claim that PID death excludes all retained open-file-description references. Trusted cooperating launchers, no direct writes, stable lock inode and root ownership are explicit premises; hostile mutation/descriptor leakage are weakening controls, not inside native confinement.

At most A+descriptor keeper+one short B probe, sequential stores, local sockets/pipes only, 4s I/O/process bounds/45s outer/256MiB per owned process, stores<1MiB. All processes are direct supervisor children for explicit reaping; no orphan child. No lock waiting loop, host configuration, native enforcement retry, production or power loss.
