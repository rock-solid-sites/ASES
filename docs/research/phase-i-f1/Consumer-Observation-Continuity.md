# Consumer observation continuity after covered loss — preregistration

C11 requires identity, provenance, project and retained consumer evidence to remain observable across covered loss, even where admission does not depend on them. Closure §5's information table treats those as observations, allows inline retention or a trusted holder, and explicitly does not design evidence ontology. F1's accepted-content fixture models fixed C and x but omits these observations; the Kernel-0 holder's finite `View` likewise has no such fields. The existing byte-continuity experiment therefore cannot establish C11.

Discriminator: construct two distinct trusted abstract consumer observation tuples, each consisting of an opaque Work Unit identity/genesis observation, created-by observation, project observation and one accepted consumer-evidence observation. The two histories have identical accepted x, grants, admission state and F1 transitions; each tuple's values differ across histories. The tuples are fixed test atoms, not an implementation schema or proposed ontology. Starting from the same reachable F1 accepted-x state, execute the inherited stop/recovery/activate-image sequence in each world. A declared consumer query projects that world's retained tuple and accepted x. Reference recovery retains the tuple and must return the exact original observation in both worlds. A bytes-only mutation drops the tuple at loss and returns `unknown` for each missing observation, while retaining x and the same F1 protected state. An independent pre-loss oracle compares each returned field and shows each C11 observation fails; it must not reconstruct or supply values to the recovered consumer. Baseline positive: both distinct tuples are returned exactly and x remains accepted. Unsafe negative: both worlds collapse to the same observable bytes/unknown projection despite requiring distinct observations. A separate test ensures dropping only a derived display cache does not change the consumer query, illustrating why the oracle checks observations rather than representation retention.

One fixed sequence per world per variant, no graph enumeration, cap execution at 30 seconds. Record every F1 event outcome and final state projection, both original and recovered query observations, field-wise comparisons, cache control, counts of histories/events, syntax result, raw output and source hashes. Abort if any inherited event does not commit or F1 reports invariant failure. This establishes a distinguishability counterexample under stipulated consumer observations, not physical persistence or a new canonical representation. Assume trusted initial observations and same current whole F1 cut; abstract recover_step and activate_image are not actual storage validation, and no executor process, currentness witness, tampering, authenticity, creation authority, source provenance verification, real consumer implementation or full C1–C13/A–L proof is tested. It does not claim that a consumer lacking an observation can infer it from x or that provenance grants authority. F1 and independent F5 review remain incomplete.
