# Direct sender versus proxied originator — preregistration

## Claims fixed before execution

* Direct-peer attribution: for each accepted kernel-delivered `SOCK_SEQPACKET` record, `SCM_CREDENTIALS` identifies its direct sending process in this single local namespace. A policy authorized for replacement PID admits its self-request and an identical record sent by that replacement after receiving it from the old process; it refuses the old process sending directly. This is a conditional observation about the declared peer policy, not a guarantee about ultimate originators.
* Ultimate-originator discrimination: the same admission rule identifies whether the initiating actor was old. Prediction: it does not; the old actor's request forwarded by replacement carries replacement's direct PID and identical request bytes, so the rule accepts it. A separately observed kernel credential on the old-to-replacement channel records the old direct sender. This is a causal fixture label for this one-hop experiment, not a general origin authentication system.

Canonical comparator: `Phase-I-Closure.md` C6 and its source-binding row say physical-producer exclusion requires a trusted association when old participants acquire current evidence; that does not settle whether a cooperating authorized replacement acting as a proxy counts as an excluded physical producer or whose intent the policy must attribute. Both interpretations stay explicit. If the intended guarantee is only direct ingress peer exclusion, per-message attribution can meet that narrow discrimination under the stated premises. If it forbids old-initiated effects despite cooperating replacement, source attribution at this ingress alone is insufficient; it additionally requires an enforceable nondelegation/trust premise or some independently justified end-to-end origin mechanism.

Controls: a replacement self-request is accepted; a direct old request over the very same transferred sink descriptor is refused by the declared direct-peer rule; then old sends the identical bytes over a separate local Unix control channel to replacement, which forwards them. The latter is accepted by direct-peer rule while an independent control-channel credential and fixed causal sequence identify the old originator. These are rule evaluations after receipt, not live protected effects or production policy enforcement.

Trust/bounds: Linux `SO_PASSCRED` enabled on both receiving endpoints before use; kernel credential records, supervisor-assigned replacement PID and one namespace are trusted. PIDs remain alive throughout capture; same UID/GID, ordinary processes, one request per case and one trusted forwarding step. `SCM_CREDENTIALS` records identify direct callers, not arbitrary historical originators; no request or process creates forged credentials. No PID reuse, namespaces, privilege manipulation, concurrent clients, network, production service, persistence, or hostile compromised kernel is tested. The supervisor sequences cases and correlates packets using separate bounded control messages, while sink payloads remain identical. Source content and original actor provenance are deliberately distinct. This is a mechanism experiment, not F1/F3 acceptance.
