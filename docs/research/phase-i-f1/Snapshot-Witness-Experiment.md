# Independently surviving current-image witness — preregistration

The F1 model explicitly assumes a trusted non-rollback currentness witness for distinguishing authentic stale from current images, and `Executor-Loss-Continuity-Experiment.md` recommends testing an independently surviving witness or fail-closed absence. Prior fixtures abstract image identity and epoch; the distinct physical snapshots here are a narrower mechanism experiment, not proof of the premise. It does not modify a service or establish a required runtime gate.

Hypothesis: a fresh receiver presented with either a real, valid old SQLite backup containing acknowledged x at epoch 0 or a real, valid current backup containing acknowledged x/y at epoch 1 can distinguish them if a trusted independently held current-image SHA-256 digest survives writer death. Receiver computes the supplied file's digest and verifies SQLite integrity before admitting it. Current with witness succeeds and reads exact x/y; old with the same witness is refused; no witness refuses even the current image. The single mutation bypasses the digest comparison (while retaining integrity validation) and admits old; a separately evaluated supervisor oracle compares accepted bytes/digest to the pre-loss committed current snapshot. Neither file's content or epoch alone is an independently trusted freshness authority.

Procedure: one SQLite writer process creates epoch-0 x, makes a consistent backup, commits y/epoch 1, makes a second consistent backup, reports their paths and digests, and blocks. Supervisor independently hashes each file, retains only the current digest as trusted witness, kills/reaps writer, and launches a fresh subprocess for each of four one-shot cases (current/witness; old/witness; current/no witness; old/witness with comparison bypassed). Each receiver opens the actual snapshot, checks integrity and reports decision and data if admitted. Require different image hashes, valid integrity for both, exact content positive, refusal of stale and absent witness, and detected mutant stale acceptance. Single deterministic history and four independent fresh receiver processes; no state enumeration or scheduler coverage. Run bounded by 30 seconds and record raw output, exact controls, hash and environment.

Trust and limits: supervisor memory and initial registration of the correct latest digest remain trusted and survive only writer loss, with no concurrent writes or mutation of snapshots after registration. SHA-256 collision resistance and local file read/SQLite integrity are premises. Digest is a full-image witness tied to these exact bytes, not a general monotonic witness, authenticated channel, cryptographic signature, secure storage, or rollback-resistant service. No host/power loss, witness loss other than explicit refusal, filesystem durability, storage adversary/TOCTOU, atomic publish of digest, recovery of live service, arbitrary images, or live transactional race is tested. Partial C5/C7 and Work Unit E/F/I only; other C1–C13/A–L and F5 remain open.
