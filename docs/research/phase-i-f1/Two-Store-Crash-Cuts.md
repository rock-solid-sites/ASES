# Authoritative record and witness crash cuts — preregistration

The snapshot witness experiment assumes the separate trusted witness already identifies the authoritative current image. It does not test the update gap. This experiment compares two orders across real SQLite-backed stores after a writer is SIGKILLed at a known committed cut. It is a discriminator of ordering consequences, not a protocol recommendation or rollback-resistant witness solution.

Fixture: two immutable, valid SQLite candidate images x/epoch 0 and x/y/epoch 1 pre-created before the test. A separate authoritative SQLite record states which image has committed; another SQLite store holds the witness's epoch and hash. Initially both name epoch 0. One writer updates each store in a separate transaction, in record-first or witness-first order. It reports after the selected commit and waits to be killed. The supervisor starts a fresh reader of both committed stores after kill and evaluates both available candidates. A candidate is eligible only if its epoch is no greater than the independently read authoritative record; it is admitted only if eligible and its actual SHA-256 matches the recovered witness hash. Independent oracle compares each admitted image's epoch and digest to the authoritative record's expected image. The oracle is not used by the witness-matching test; the authority eligibility rule is an explicit premise, not a demonstrated production mechanism.

Pre-run hypotheses: record-first, after only authoritative record commits epoch 1, leaves epoch-0 witness and admits old epoch 0, which the oracle marks stale; new is refused. Witness-first, after only witness commits epoch 1, keeps authority at 0: old mismatches witness and the pre-created new image is ineligible, so both refuse. Completing both updates in either order yields new accepted and old refused; initial cut accepts old. For each of five cases (initial, both first-update cuts, both completed orders), use independent stores and a separate writer process, kill/reap after its reported cut, then a fresh recovery reader. Report actual recovered values, both candidate decisions, independent oracle results, PIDs/exit status, exact command, hashes, SQLite integrity, and no graph enumeration; bound execution to 30 seconds.

Assumptions: committed SQLite transactions survive process SIGKILL on the same live host; supervisor pre-created images and trusted image-to-epoch mapping, authoritative record reading, eligibility, serialization, no intervening operations or file mutation, and correct non-rollback reading of both stores. Witness-first intentionally assumes an authority eligibility check at consumption; if missing, a future/prepared image can be admitted before authoritative commit, a separate issue, not an established safe protocol. No crashes within SQLite commit, power loss, corruption, adversarial rollback, durable cross-store transaction, concurrent requests, external effects, or general recovery protocol. Partial C7/C12 and Work Unit E/F only; no F1/F5 completion.
