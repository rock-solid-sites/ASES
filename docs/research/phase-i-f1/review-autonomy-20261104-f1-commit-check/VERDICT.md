# Independent first verdict: held-reader COMMIT busy

**Verdict: supported for the two observed runs, with the test instrumentation and scope below; not a proof.** No product defect or setup failure was found for this narrow claim. The original raw record and one disposable rerun each show a completed holder UPDATE, a COMMIT returning SQLite code 5 (`SQLITE_BUSY`) with the transaction still active, completed ROLLBACK, client EOF, and recovery of the previously acknowledged state. The released-reader control commits, replies with the new state, and both independent and cold-holder reads recover that state. Confidence is evidence-based and bounded to these executions and the declared rollback-journal profile.
