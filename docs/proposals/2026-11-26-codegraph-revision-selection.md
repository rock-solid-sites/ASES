## Proposed interface
Keep exact existing issue title `[codegraph] owner/repository` and question body semantics for default HEAD. Optional suffix `@<revision>` in title, e.g. `[codegraph] owner/repository@refs/heads/feature/example`, `@refs/tags/v2.2.1`, or full 40-hex commit. Explicit branch/tag namespaces avoid ambiguous short names; support short branch/tag names only if unambiguously resolved, otherwise reject (optional convenience, not necessary first implementation). Add optional revision input to workflow_dispatch and third optional script argument. Default means actual remote default HEAD, not literal main. No private repository, PR fork discovery, local/uncommitted state, arbitrary refspec, or new plugin. PR head may be addressed via its public source repository plus explicit branch/commit, not implied merge ref. 
Resolve and fetch requested source from the validated public repository, shallow where practical, verify expected ref/object and commit type (peel annotated tags), checkout detached exact commit; no fallback on nonexistent, ambiguous, moved or unavailable requested ref. Use exact Git ref validation and quoted arguments, reject leading option, whitespace/control, traversal/ref expressions/refspec syntax and overlong invalid input; do not evaluate user text in shell, keep repo/title parsing separate. Avoid arbitrary Git revision expressions and new protocol/host. Public-only check must continue. For SHA no guarantee server makes unreachable object fetchable; report unavailable without substitution. Record requested revision and actual resolved commit in returned answer, including fresh/restored and run URL. Ensure source used for index/query is the same resolved commit, with no second branch HEAD lookup. Branch movement between resolution and fetch should either use the resolved SHA or fail closed rather than silently change snapshot.
## Cache
Keep current key and manifest unchanged unless actual incompatibility demonstrated: codegraph/v1/<repo>/<resolved-commit>/codegraph-<version>-linux-x64. Branch and tag pointing to same SHA reuse identical index; branch advancing produces a fresh index, older commit remains addressable. No ref-based cache keys, no duplicate index per branch, no broader B2 permissions or moved secrets. Preserve existing integrity/manifest/archive checks and fail-closed behavior.
