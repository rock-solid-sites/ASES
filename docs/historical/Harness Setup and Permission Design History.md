# Harness setup and permission design history

**Purpose:** explain the choices, trade-offs and evidence behind the former OpenCode/Claude/Crosslink environment. This is a historical research map, not a setup guide, security guarantee or launch authorization. Current decisions are summarized in the [AI Orchestration Guide](../methodology/AI%20Orchestration%20Guide.md), [task-scoped method](../methodology/ASES%20Task-Scoped%20Information%20and%20Handoff%20Method.md) and applicable [current skills](../../skills/current/README.md).

## Disposition and exact source

The old IT3812/VPS environment coupled agents, role definitions, plugins, hooks, MCP servers, Crosslink issue state and model selection. The operator's October 30 correction in [permissions.md](https://github.com/rock-solid-sites/ASES/blob/dc001af09d57050b5234ca794996950dd9e83c0d/.opencode/permissions.md) explicitly retired crosslink-guard; the November 21 accepted [task-information architecture](../architecture/Task-Scoped%20Information%20Architecture%20Decision%202026-11-21.md) removed mandatory session files, and the current launch/review methods use independently authorized routes. The legacy configuration must not silently load in a new repository session. Preserve the old bundle together rather than weakening it selectively, or inventing an untested replacement.

Exact pre-reorganization snapshot: [ASES dc001af09d57](https://github.com/rock-solid-sites/ASES/tree/dc001af09d57050b5234ca794996950dd9e83c0d). Archived copies use the same original Git blobs; the former directory structure can be recovered from that snapshot. Do not execute archived configuration directly; its environment, permissions, dependencies and model routes are not verified for current harnesses. The move changes source discovery only, not any deployed host's configuration.

## Current execution boundary

For a real launch select the actual host, launcher, model and approved funding route with current skills. The independent review recipe in [ases-plugins](https://github.com/rock-solid-sites/ases-plugins/blob/main/docs/INDEPENDENT-REVIEWER-WORKING-RECIPE.md) operates independently of this old bundle. A new agent workspace must verify effective configuration and role restrictions rather than assuming either the historical guard stack or permissive defaults are approved. WNASES-19 owns actual instruction exposure and role permission checks, WNASES-23 fresh-chat skill selection. No runtime test, provider call, security guarantee, or activation follows from archival relocation.
