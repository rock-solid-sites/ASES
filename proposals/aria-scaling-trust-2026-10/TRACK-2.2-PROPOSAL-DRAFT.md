### 0. Summary (under 500 words)
AI agents can increasingly execute complex tasks using existing operating systems, tools, networks and services, yet a critical security question remains unanswered: **which authority actually permits a consequential operation at the instant it happens, and can that permission be enforced when the agent, its operator or its supervisor fails or is replaced?** A model instruction, an access-control record, and a confident report are not sufficient if an old process retains a usable file descriptor, credential or external-service route.

We propose an open-source, reusable authority-enforcement and conformance component for agentic systems, grounded in the Kernel-0 and Work Unit-0 research program. Our core research treats authorization as a current-state-dependent predicate over the exact proposed effect, accepting a whole transition only when guards, effect relation and invariants agree. Work Units retain bounded work and accepted content independently of the lifetime of any particular agent process. This is deliberately narrower than designing a new general-purpose agent, network stack or operating system: existing systems provide computation, while the protected boundary supplies demonstrable limits on consequential operations.

The project has substantial but scoped prior evidence. A fixed transition-logic Kernel-0 realization passed 4,945,272 bounded oracle comparisons and synthesis-level equivalence checks under declared finite-profile and trusted-ingress assumptions. Subsequent ingress-reduction experiments tested a simpler protected-lane hypothesis. The ongoing Work Unit program has executable bounded reference models, 46 abstract hostile-history replays with 16 discriminating mutations, and two bounded host experiments: explicit mediator revocation, and a selected holder-loss configuration in which a confined worker was denied a new protected read after the holder/mediator process was killed while CPU-only computation continued. A deliberately surviving mediator with cached authorization violated that rule and was detected; other experiments exposed inherited-descriptor bypasses. These findings do not establish general confinement. These are **research results, not proof of a completed deployment-quality security substrate**.

We seek support to turn the semantics and experimental mechanisms into a usable, independently testable agent-side component: a minimal enforcement boundary for selected resource attachments, precise machine-readable effect and authority decisions, observable failure/recovery behavior, and a hostile conformance suite that distinguishes successful security claims from vacuous denials. We will demonstrate useful delegated work involving distinct principals and deliberately adversarial actors, measure security failures alongside task utility, and publish the component and reproducible evidence under MIT/Apache-2.0 dual licensing for funded deliverables.

The intended contribution to ARIA Scaling Trust is the *enforcement layer between security policy or protocol decisions and actual consequential actions*. It complements funded efforts in protocol design, negotiation, auditing and cryptographic evidence. By making authorization boundaries falsifiable rather than merely asserted, it could give Arena entrants and other agent platforms a reusable foundation for trustworthy coordination.

### 1. Program and technical case

#### Track and distinctive problem
**Track 2.2 — reusable components.** ASES addresses a distinct operational problem: **authority-to-effect correspondence**. Many systems can derive or express a policy; a different system component must reliably decide, at the effect boundary, whether an actual file, network, credential, storage or service operation is currently permitted. An agent sandbox alone does not prove that every protected route is mediated, that obsolete authority is excluded, that accepted content survives selected failures, or that recorded authorizations match irreversible effects.

The specific contribution is a small, inspectable component with an explicit failure-profile contract and an evidence-based conformance harness. Within ARIA's component taxonomy, it occupies the implementation/assurance boundary between a *Security Reasoner* producing a policy or protocol, a *Protocol Implementer* carrying out selected authorized operations, and a *Security Auditor* checking the resulting trace. The proposed component does **not** itself generate negotiations or cryptographic protocols: it receives an explicit authorized effect contract, mediates a declared real operation, and emits evidence that a checker can challenge. This is an additional integration capability for other agent systems rather than a replacement for secure execution products or an existing funded protocol tool. Track 2.3 forward deployment/adoption is a separate future solicitation, not the funded basis of this Track 2.2 application.

#### Scientific/technical hypothesis
**Hypothesis H:** For a declared finite class of delegated agent operations and physical trust premises, an implementation with a minimal authoritative state-transition boundary plus independent durable Work Unit state can enforce current authorization on selected real effect routes, retain accepted work across executor loss, and expose enough evidence for independent conformance and adversarial testing, without a permanently trusted agent reasoning loop.

The hypothesis is falsifiable by a single post-revocation or post-failure forbidden effect through an in-scope route, a missing accepted byte after covered recovery, a replayable stale holder, a partial commitment falsely acknowledged as whole, or a failure to make useful authorized progress.

#### Existing results and their limits
1. **Kernel-0 RTL:** finite-profile synthesizable transition logic, with no general processor or interpreter in the declared authority mechanism; 4,945,272 comparisons across three profiles, including correspondence and synthesis checks. This does not prove physical silicon, arbitrary concurrency, hardware wiring, trusted ingress or complete agent confinement.
2. **Ingress reduction:** experiments on replacing caller-supplied identity/authenticity claims with protected fixed source lanes. Conditional on physically trustworthy lane separation; physical unforgeability is not demonstrated.
3. **Work Unit formalization:** finite model witnesses for replacement, retained x/y through two modeled recovery losses, a capacity-one resource, acyclic-order obligations, current-versus-stale images and targeted malicious mutations. The broad C1–C13 / A–L proof obligations and concrete realization correspondence are incomplete.
4. **Host enforcement:** a Landlock-confined worker passed the explicit revocation test; a later selected-profile experiment demonstrated an authorized pre-loss read, H=M process death observed by SIGKILL/reap, 392,488 counted CPU iterations, denial of a later retained-socket read, and denied direct path/symlink/no-op write opens. An intentionally surviving stale-grant mediator provided an observable negative control. General source binding, actual cold recovery, external effects, arbitrary route coverage, and full F3 lifecycle remain open.
5. **Adversarial catalogue:** T01–T24 scenarios with 46 executed *abstract replays* and 16 discriminating mutation controls. A selected T05 adapter additionally checked pinned F3 host traces and negative controls; this is **not** full physical T05 or F5 review.
6. **F3 lifecycle follow-up:** selected L1–L4 experiments report bounded accepted-content, worker-replacement, holder-loss and recovery behavior. A separate L5 standalone three-case mediated-write fixture distinguishes positive, restriction-preserving and restriction-dropping cases; it does not prove a continuous L4→L5 history or an actual accepted-storage read at request time. Three distinct-model source reviews of the pinned L5 fixture have returned `partial` (reports @ `831f2bb9c1fe6b30e09520acb249043b72a29bc0`). The reviewers corroborate the latent-ceiling positive/negative discriminator, but also identify absent dependent D, non-transitive ancestor constraints, hardcoded activation, constant-sourced accepted-content reads and untested mutation resilience; no F3/F5 closure or independent human security attestation is claimed.

These results are documented in the evidence ledger. We will publish counterexamples and unresolved assumptions as first-class outputs, not present them as passing guarantees.

#### Proposed deliverable and interfaces
The funded product will expose a narrow, versioned interface for: (i) proposing a fully specified operation against a named bounded Work Unit and declared capability; (ii) receiving an authorized whole-effect decision or denial with an explicit scope and state/dependency reference; (iii) invoking a protected adapter for a supported effect rather than handing an ambient credential to the untrusted agent; and (iv) exporting machine-readable observations for a separate checker. This is a *target interface*, not an existing implemented API or a commitment to any particular transport, language or isolation architecture. Interface and realization candidates must pass ASES's exclusion-first assurance selection.

The reference Work Unit is an object with explicitly bounded content, authority, provenance, capabilities and failure semantics. Agent processes remain replaceable; the implementation must avoid confusing a supervisor's cached grant with current authority. When the authority holder is lost, in-scope protected operations fail closed while permitted internal resource-backed computation may continue. Accepted content remains protected and recoverable under the declared process-loss/current-storage assumptions.

#### Test case and Arena relevance
An Arena-relevant target scenario has **two principals with independently scoped authority** and distinct delegated agents interacting with a disposable service. The agents perform an authorized shared task; one attempts to reuse an obsolete permission after revocation or replacement while the other continues legitimate work. A separately instantiated red-team participant tries impersonation, replay, inherited-handle bypass or unauthorized effects through an in-scope adapter. The security property is checked at the actual effect boundary, not inferred from the agents' messages. The honest agents must also complete a useful task: a component that denies everything fails. This multi-principal scenario is a **funded integration target**, not a demonstrated capability of the present single-holder F3 fixtures.

Measures: proportion of supported harmful-history tests excluded; positive task completion; differences between modeled and observed histories; mutation sensitivity; supported route coverage; resource/latency overhead against baseline; recovery behavior under explicitly covered failures; and integration cost for a second agent harness. Report the denominator and exclusions for every metric. Do not claim zero security failures outside the covered boundary.

#### UK industry infrastructure validation — conditional field-research objective

To establish practical UK value beyond a research prototype, the project will evaluate the component in two concrete operational domains: **software delivery/CI–CD** (an agent performing authorized repository/test activity but unable to use stale deployment privileges) and **managed data/cloud API work** (two distinct principals with separately scoped access to a disposable service or data tenant). The project will measure legitimate task completion, detected unauthorized-effect attempts, failure recovery, auditability, integration effort and latency/resource overhead against existing native access controls. These are selected test domains, not claims of existing customer adoption.

The funded Track 2.2 milestones focus on **open tooling, integration, reproducible adversarial evidence and external assurance**, not a forward-deployed adoption contract. Seek UK-based technical evaluation and operator feedback during the research; two permissioned UK evaluations and one low-risk operational pilot remain **conditional stretch targets**, dependent on partners, written authorization and independent security gates. First use synthetic/consented data and isolated staging environments. No critical-infrastructure or uncontrolled production penetration test is proposed. If no participant is secured, publish reproducible UK-relevant public testbeds and document the recruitment outcome rather than claiming a completed pilot.

This creates a defensible benefit to the UK: open infrastructure and documented security evaluations available to UK software, managed-service and AI-security companies; focused UK-based integration/security expertise as required by actual work; public reproducible evidence, and feedback from real operators. No particular UK partner, contract or commitment is asserted. The program's staged pilot safety, baselines, stopping conditions and UK-benefit evidence are detailed in `UK-INDUSTRY-VALIDATION-OUTCOME-FIRST.md`.

#### Key risks and response
- **Actual-effect bypass:** inherited descriptors, aliases, process descendants, alternate credentials, network/sink acceptance, and OS policy races may defeat metadata-only sealing. Use concrete route inventory and hostile tests; restrict the selected attachment until all claimed paths are accounted for.
- **Trusted base too large:** OS, storage, runtime, toolchain and mediator remain trusted to the extent the guarantee depends on them. Report the entire actual TCB; test reductions rather than asserting processorless RTL eliminates host trust.
- **Loss/currentness ambiguity:** process-loss tests cannot prove power-loss durability or rollback resistance. Publish separate failure profiles, and withhold activation if currentness is unavailable.
- **Compositional mismatch:** independent local checks may not explain a complete observed history. Compare whole histories against one coherent admissible order and compatible recovery cut.
- **Novelty and cost:** a novel mechanism may be costly to validate, adopt and maintain. Compare it empirically with existing host facilities and reusable open-source mechanisms before freezing a production realization.
- **Adoption/generalization:** an abstract kernel could remain isolated research. Build to a stable narrow component interface and evaluate interoperability with independently developed agent systems, rather than building an entire agent platform.

#### Differentiation and portfolio complementarity
ARIA's published portfolio includes the University of Edinburgh's agentic protocol security reasoner, Dovetail's protocol synthesis, ProtoSage/ProtoBench protocol auditing, Project HAMMER's negotiation security, and CCTI's cryptographic trust infrastructure. These tools address protocol creation, interaction, audit or trusted facts. Our proposed boundary addresses a distinct failure mode: a policy can be sound and its protocol verified, while actual operation through an old descriptor, credential or holder remains unauthorized. An enforcement-and-conformance component can *consume* their decisions and demonstrate whether a real effect met them; actual interoperability is future work rather than an existing partnership. See the October 7 portfolio map and the companion positioning memo.
